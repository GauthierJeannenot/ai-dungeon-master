# XGE Downtime ledger and Work — bounded first tranche

Optional XGE *Downtime Revisited* is OFF until `adopt_xge_downtime` receives the MJ's explicit decision and existing fact. This tranche delivers **Work only**, not the whole downtime chapter. Existing PHB ordinary crafting/training remain distinct.

## Source and user decisions

Canonical supplied `rules/books/xge.md`: Downtime Revisited lines1910–1995, particularly Resources/Resolution/Complications1983–1995, and Work/Wages/Work Complications2495–2522. Actual source metadata/section/hash are obtained from the existing rules library with exact fixed headings; its parser/index is unchanged. At least8actual hours on each of5distinct days; days need not be consecutive. The source requests extra complications and possibly double costs when work takes more than twice its required time. Work has no printed gp base cost; **no invented doubled tariff**.

## Public procedure

1. `adopt_xge_downtime({eventId,decisionFactId,explicitlyAdopted:true})` retains the original decision/source and immutable clock basis.
2. Establish an actual temporary job with a real existing capable nearby employer, fact and current supported worksite. `start_downtime_work` retains its original check choice, owned tool if applicable, map/room/cell/support and employer identity. It creates no NPC, proficiency, equipment, job from prose, prior work or reward.
3. `work_downtime` performs1..28800 actual seconds through the existing clock/rest/nutrition/event preflights. The explicit MJ classifies real light/strenuous activity. No rest is finished or benefit granted. Five different dates must each contain28800 measured seconds. Waiting never grants effort.
4. `resolve_downtime_work` retains one original source check and held reaction continuation before any award. One d100 occurrence roll triggers complications on1–10. Separately choose an actual d6 table roll or an explicit MJ table line with its existing fact, as allowed by XGE's general Complications procedure. Choosing a line never forces occurrence. No reroll by nonce.
5. `adjudicate_downtime_work` persists bounded discretionary decisions before settlement. After ten tracked dates from first actual effort, choose a new deadline (within365dates of first effort), one extra source Work complication with its actual fact, and optional **explicit** payable denominations, including zero. This is MJ discretion, not a RAW tariff. A reduction below the last printed Poor row requires its own explicit Squalid/Wretched/unpaid choice and fact. **Every separate below-table reduction requires a separate decision**. Unpaid employer trouble grants no cash or coverage and keeps all historical complications.
6. `settle_downtime_work` grants one retained outcome. Only a surviving21+ Comfortable+25gp result grants2500cp; actual denominations are selected explicitly, checked for projected carrying before credit, never defaulted/exchanged. Other outcomes receive zero cash. Dated lifestyle rights have no item mass. Required complication facts and existing coworker/rival identities are retained; rival hooks require an actual prior rivalry fact, and the cult/employer row has no rival hook. No NPC attitude, extortion payment, faction, criminal organization or new actor is executed automatically.
7. `inspect_xge_downtime` is pure. `cancel_downtime_work` retains all real effort/expenses/complications, with no refund; a completed week/result cannot be erased to avoid its chance or obtain another reward.

## Shared time and physical limits

The clock basis is the **existing engine epoch0**, with day `floor(worldTimeSeconds/86400)`, retained canonically at adoption as `engine_epoch_0_86400_seconds`. It is never the campaign display-calendar anchor, a supplied date, the adventure date, or the adoption instant. Configuring a display calendar cannot change Work/crafting/training `calendarDay`, nutrition/sleep anchors or source world time. A segment crossing actual midnight refuses before time/cost; split explicitly at the boundary. Hours on different dates do not combine into one Work day.

This first shared ledger represents **one8hour effort budget per actual date across Work/ordinary crafting/training**, in both directions, including cancelled histories and partial intervals. This is a technical tranche limit, **not a RAW universal maximum8hours of work per day**. No second credit for a physical interval. Shared budget sums the intersection of every actual `[from,to]` interval with each epoch0 day, never legacy display/credit labels. A legacy interval crossing midnight contributes only its physical seconds on each side; historical labels are not rewritten. W22 individual craft/training hydration itself already rejects a forged label999, and the new ledger independently refuses that adversarial mismatch. Multi-job overwork, other XGE activities and retrospective credits are outside scope.

The continuing job agreement and MJ table choice are durable existing facts unrelated to item custody (`expires:never`, no `subjectItemId`). This does not prevent actual item transfers, room/map purges or employer death; physical job availability follows its ordinary guards. Public `record_scene_fact({replaceFactId})` refuses replacement while its job remains active, and protects the exact MJ choice fact while its Work check is held; new unrelated phase facts remain available. After result, the already-snapshotted table choice may be replaced without erasing its original history. SQL rejects missing active job qualification. The real original worker/site/tool/employer must remain capable and reachable. No remote work, automatic movement/landing, unknown employer altitude flattened to ground, air supply, resurrection or suppressed due affliction is inferred. Interrupted/due procedures must be resolved explicitly through their own existing tools. The operation never manufactures a MCP call to nutrition/rest/service/calendar.

Work complication6 affects **six NEXT tracked Work weeks**, never its source week or a roll already held/resolved. This tranche refuses cancellation **after any actual effort** while lazy-reputation accounting applies, including its original extra-delay source project. Thus partial abandoned jobs cannot prolong/reset the counter; general partial-abandonment reputation accounting is not modeled. Zero-effort cancellation remains possible. This is an explicit engine subset limit, not a claim that RAW forbids abandoning a job.

Histories are bounded (64projects,4096receipts,1024segments/project,16complications/decisions) with refusal before mutation rather than eviction. Structured canonical command witnesses retain adoption, original job/tool/site, every actual interval, held result, original occurrence/selection, arbitration, settlement and receipt from the first SQL stage. JSON object key order is harmless. Validation does not freeze the live wallet against later legitimate spending.
